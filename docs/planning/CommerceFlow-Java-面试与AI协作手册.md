# CommerceFlow：面试与 AI 协作手册

配套：[总计划](./CommerceFlow-Java-项目总计划.md) · [每日计划](./CommerceFlow-Java-56天每日计划.md)。

## 能力与证据

项目重点是Java交易后端；不能承诺覆盖所有岗位。每项能力都附实际实现/测试/原始报告：Java并发→库存竞争实验；Spring事务→回滚注入；MySQL→执行计划/MVCC实验；Redis→Lua恢复；MQ→重投与死信；微服务→超时补偿；JVM→JFR诊断；工程→CI与干净部署。基础知识与算法仍需独立练习。

## 60 个面试问题与答题线索

每题用“场景→方案→失败边界→证据”讲述。下面是提纲，答案必须以实际代码为准。

**1. HashMap为什么扩容？**

负载与桶冲突影响查询；解释哈希、equals/hashCode及扩容成本，不把均摊复杂度当最坏保证。

**2. ConcurrentHashMap解决什么？**

进程内并发映射访问；不能保证多个API调用或数据库扣库存构成原子事务。

**3. 泛型擦除有什么影响？**

运行时类型信息与编译期约束不同；结合DTO集合、反射序列化说明边界。

**4. Stream并行一定更快吗？**

取决于数据量、任务性质和共享线程池；数据库/远程调用不应随意parallelStream。

**5. volatile能保证余额加减安全吗？**

保证可见性及相关顺序约束，不保证复合读改写原子性；数据库金额靠事务。

**6. synchronized、CAS如何选择？**

理解互斥与原子比较更新；CAS存在竞争重试，仍不跨实例保护资源。

**7. AQS和线程池怎样关联到项目？**

解释等待队列和同步机制；展示有界任务队列、拒绝策略、关闭与监控。

**8. ThreadLocal为何可能泄漏？**

线程池复用和未清理请求状态；finally清理，不用它替代跨消息的显式身份。

**9. Java21虚拟线程解决什么？**

改善阻塞任务线程成本，不能消除DB连接池/下游容量限制；用对照实验说明。

**10. JVM问题怎样从现象查起？**

CPU看热点/线程，内存看分配与保留，延迟看GC/锁/池等待；记录JFR证据。

**11. IoC和自动装配是什么？**

说明Bean定义、条件配置、依赖注入；结合项目启动和依赖树定位实际配置。

**12. AOP事务为什么自调用失效？**

典型代理调用没有经过代理；展示重构服务边界或显式事务方案，不背结论就结束。

**13. @Transactional能跨Feign吗？**

只能覆盖本地管理的事务资源；远程服务用持久状态、幂等命令和补偿协调。

**14. 事务传播和回滚有哪些坑？**

检查异常类型、捕获异常、代理边界、REQUIRES_NEW独立提交；用失败注入证明。

**15. Filter与Interceptor区别？**

Servlet过滤链与MVC处理链所在层不同，Spring Security过滤器承担认证授权。

**16. JWT退出如何生效？**

撤销refresh并说明access存活窗口，敏感动作查用户状态；不能说删除前端token就全局失效。

**17. JWT有签名为什么还验金额？**

认证消息来源不代表业务对象、金额、币种、状态正确；签名与业务校验都必需。

**18. 买家怎么越权查看订单？**

猜ID访问详情/退款/下载；服务端用可信userId校验归属，不能只隐藏列表。

**19. MyBatis-Plus是否自动解决SQL问题？**

生成CRUD仍需审查条件、分页、批量更新、事务和索引；查看实际SQL。

**20. REST重试何时安全？**

HTTP方法名称不是全部；业务命令需幂等键、摘要及唯一业务约束，未知结果先查。

**21. 为什么发生超卖？**

两个请求都读到旧available后写入；条件SQL或锁内校验并检查affected rows。

**22. 库存三个数量为何这样定义？**

physical未发货实物，reserved已占用，available差值；支付不再次扣实物，发货同时扣两者。

**23. 多SKU怎样原子预占？**

同库存服务内按固定顺序事务处理；一个不足全回滚；跨服务不要假装有同一事务。

**24. MVCC与锁有什么关系？**

快照读与当前读不同；RR下锁定读/更新不能照搬普通SELECT快照结论，做双会话实验。

**25. RC/RR怎样演示？**

明确事务开始/第一次读/另一事务提交的时间；记录可见值与范围查询，不只背隔离级别表。

**26. 索引为什么没被使用？**

成本估计、选择性、表达式/类型转换、前缀与排序等因素；看真实执行计划验证。

**27. 深分页怎么改？**

可用稳定排序的created_at+id游标，说明随机跳页和并发新增的取舍。

**28. 死锁怎样处理？**

固定锁顺序、短事务、合适索引，有限重试整个事务；业务库存不足不反复重试。

**29. 金额为什么不能double？**

十进制金额有精度风险，使用分或严格BigDecimal，舍入规则/溢出/JSON表示明确。

**30. 唯一键为何比先查存在更可靠？**

并发先查都可能不存在；数据库约束裁决竞争，应用映射冲突为可理解结果。

**31. 订单幂等如何设计？**

用户+操作+key唯一，规范化请求摘要，同键异内容冲突，结果引用与业务同事务。

**32. 价格为什么做快照？**

商品以后改价不能改变已下订单；服务端结算和快照保证历史可解释。

**33. 关单时支付状态未知怎么办？**

保持CLOSING，查询/重试提供方，确认关闭才释放；超时不代表未付款。

**34. 支付与关闭谁决定胜负？**

提供方原子状态转换裁决外部扣款，本地接收回调/查询后收敛；迟到创建也需关闭墓碑。

**35. 关闭后发现扣款怎么办？**

异常对账与退款，不能无条件复活已释放库存的订单；记录告警和最终结果。

**36. 退款超时能换退款号重试吗？**

不能；固定原退款号查询/重试，避免生成两笔外部退款。

**37. 退款和发货并发如何处理？**

订单履约状态条件迁移裁决；退款先受理禁止发货，已发货进入退货验收分支。

**38. 退款是不是立即加库存？**

未发货释放reserved；已发货先退货验收再恢复physical，重复事件不可再加。

**39. 优惠券超时释放为何还查有效期？**

预占释放不代表重新有效，已过期应变EXPIRED；退款退券与否是显式产品规则。

**40. 拆库存服务后预占迟到怎么办？**

取消墓碑/操作版本防悬挂；迟到Reserve不能覆盖终态RELEASED，保留幂等结果。

**41. Outbox解决什么？**

业务和发送意图同事务，避免提交成功却无消息意图；不消除重复发送。

**42. 发送成功后进程崩溃呢？**

可能尚未标记发送，恢复会重投；消费者去重和业务事务保障一次业务效果。

**43. 消费者先标记已处理再业务更新安全吗？**

若不在同一事务，会丢业务；inbox和更新同本地事务，成功后ACK。

**44. RocketMQ事务消息能跨库ACID吗？**

不能，它协调本地事务与消息可见性的最终一致性；消费端仍需处理失败与重复。

**45. 顺序消息能代替状态机吗？**

不能假设跨topic全局有序；重复/迟到/版本变更仍要条件状态处理。

**46. 死信怎么重放？**

先定位毒消息/修复根因，受控重放仍走幂等，保留操作审计和结果。

**47. Redis Lua原子性边界是什么？**

单次脚本执行在Redis内原子，不含MySQL/MQ；Cluster多键需同slot。

**48. Lua扣令牌后宕机怎么办？**

数据库先保存attempt意图，Redis按attempt留结果，扫描恢复并补outbox；不能只盲目返库存。

**49. Redis数据丢失如何重建？**

暂停入场、对账持久占用与待处理attempt、切epoch隔离旧请求；数据库最终约束防超卖。

**50. 分布式锁解决所有一致性吗？**

过期、网络延迟、旧持有者恢复会破坏假设；需要幂等、条件写/版本和持久业务状态。

**51. Nacos与Feign分别做什么？**

注册发现与服务调用；说明客户端兼容、超时、负载均衡、内部身份，不把加入依赖当治理完成。

**52. 熔断和限流怎么区分？**

限流限制进入速率，熔断隔离持续失败依赖；隔离舱限制资源占用。

**53. 重试为什么可能雪崩？**

多层重试放大流量和等待；统一预算、退避抖动、有界次数，幂等写才可安全重复。

**54. 缓存删除失败怎么办？**

持久失效任务+重试+TTL；还要考虑旧读晚回填；交易价格重新查权威源。

**55. p95与吞吐怎么解释？**

说明硬件、数据与负载；受理吞吐不等于最终订单吞吐，业务拒绝与5xx分列。

**56. 怎样定位慢接口？**

trace→下游/DB池/锁等待/慢SQL/CPU/GC，基于证据优化同一负载复测。

**57. 指标为何不能随意标订单号？**

标签基数爆炸；订单细节用日志/trace，指标保留有限维度。

**58. Testcontainers比mock多证明什么？**

真实引擎的约束、SQL、事务与Lua行为；mock适合纯规则，不证明MQ重投。

**59. 备份完成等于能恢复吗？**

必须恢复到测试环境并检查业务对账、迁移和查询；镜像回滚不等于数据库回滚。

**60. AI辅助项目如何证明你会？**

独立解释核心事务、复现故障、修改小需求并写验收；贡献记录说明实际判断，不编造优化数字。


## AI 协作方式

每天先定一个可验证Issue，限制改动范围。AI辅助阅读源码、提出方案、实现局部代码、生成故障候选与审查diff；你确认业务规则，阅读关键事务和SQL，亲自验证失败路径。核心问题不能只让同一个实现自动生成“证明自己正确”的测试，至少独立列出反例和数据库后置断言。

每日开工提示词：
```text
今天执行 CommerceFlow 第 X 天。先读取计划、仓库约定与现有相关实现。
列出需要保持的不变量、涉及的状态和事务边界，再分小步实现。
复用已有代码，不做无关重构，不随意升级全套依赖。
关键库存/支付/MQ行为使用真实数据库或Broker验证。
最后报告实际命令和结果、未验证项、差异与合理提交拆分。
```

交易审查提示词：
```text
检查当前diff：重复请求、同键不同内容、并发最后一件库存、多SKU中途失败、
支付与关单竞争、退款与发货竞争、提交后响应丢失、重复或乱序消息。
指出具体代码路径、失败窗口及数据库后置断言。
重点检查事务代理/tx边界、条件更新行数、唯一键、锁顺序和补偿幂等。
不允许用按钮禁用、Redis锁或mock成功代替业务正确性证明。
```

秒杀恢复提示词：
```text
逐个枚举attempt落库、Lua预扣、状态更新、outbox、MQ成单之间的崩溃点。
每一步说明哪个持久事实可查询、谁重试、谁补偿、如何防止重复回补。
检查Redis标记过期、全量数据丢失、旧epoch请求与新epoch并存。
输出可运行故障实验；没有做的保证明确标为未验证。
```

## 每日提交与周发布

建议每日2–4个有效提交：一项可工作的实现、必要负例测试、真实修复或设计说明；轻量复盘日允许少提交。不倒改时间、不空提交，不把每个文件拆成一次提交。

示例：
```text
feat: reconcile payment closure before releasing stock
test: race payment success against order timeout
docs: explain unresolved payment state recovery
```

每周一个里程碑，短分支/PR说明问题、行为、验证和限制。学习日志记录Issue、实际变更、自己做的判断、AI初稿问题、实际命令与结果、未完成项、commit链接。AI总结必须核对后再保存。

## GitHub 与面试交付

README首屏放真实截图、演示视频、业务定位和启动入口；docs提供ER/状态图/时序、测试矩阵、失败演练、性能报告和架构取舍。性能报告必须留硬件/版本/commit/数据/负载/原始输出，不把压测目标写成已实现数字。

90秒介绍模板：我实现了一个Java电商交易平台，贯通库存预占、订单、模拟支付和履约退款。核心工作是幂等请求、数据库防超卖、支付与关闭仲裁、Outbox/Inbox和失败补偿。后续把库存拆为独立服务，用真实故障验证最终一致性，秒杀通过Lua入场控制和持久attempt恢复。所有效果以测试、故障记录和实测报告为证据。尚未完成的部分改成计划时态。

- 基于Java21/Spring/Vue实现商品、订单、优惠、支付退款及履约闭环，提供可复现Docker部署与CI。

现场训练：不看AI答案写条件扣库存SQL、幂等事务伪代码、支付关闭时序和Lua恢复表；用两个SQL会话展示RC/RR；从JFR中指出一个真实热点。每周选2–3道基础算法题，能解释复杂度和边界。

## 发布检查

- 全新clone按说明启动、迁移与seed；开发工具和模拟危险入口不公开。
- 用户权限与对象归属、库存/金额/券、消息去重都有负例。
- 订单中间态可查询、可恢复；没有依赖一次HTTP成功返回的永久悬挂。
- 演示既展示成功闭环，也展示失败后收敛。
- 已实现、设计目标和未来扩展清楚区分；两个月作品不包装成生产履历。
